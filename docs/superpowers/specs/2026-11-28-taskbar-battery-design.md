# タスクバーにデバイスの絵と残量を並べて出す（fork だけの機能、fork Issue #16）

## 目的

トレイのバッテリー表示は、5% 刻みの電池の絵だけで、デバイスの種類が入っていない。`perDevice` モードで何台も出すと、**どれが何か分からない**（作者の言葉: 「複数出した時にどれが何かわからないのは微妙」）。

そこで、Windows 11 のタスクバーの上、トレイのすぐ左に、接続中のデバイスごとに「種類の絵＋残量」を横に並べて出す。見え方と出し方は、作者が別に作った `inzone-auto-switch` のタスクバー表示（`../inzone-auto-switch/docs/superpowers/specs/2026-11-26-taskbar-battery-design.md`、実機確認済み）に合わせ、そのコードを移して使う。

本家には PR しない。fork の決まり（`docs/fork.md`）どおり、本体は新しいファイルに置き、本家のファイルへの変更は `// fork:` の目印付きの数行のつなぎだけにする。

## ゴール / 非ゴール / アンチゴール

- ゴール: 設定で ON にすると、メインのモニターのタスクバーの、トレイのすぐ左に、接続中のデバイスが `[絵] 82%  [絵] 45%  [絵] 18%` のように並ぶ。
- ゴール: 絵でデバイスの種類が分かる。ウィンドウのカードと同じ絵（`src/renderer/icons.js` の種類別の絵。カードで絵を変えていればその絵）を使う。
- ゴール: 残量が少ないと数字の色が変わる。充電中は分かる印が付く。
- ゴール: 設定画面の ON/OFF で、再起動せずに切り替わる。
- ゴール: 本家の取り込みで衝突しにくい。本家のファイルへの変更は、`// fork:` 付きのつなぎだけ。
- 非ゴール: トレイの表示を変えること。トレイはいまのまま残し、両方を同時に出せる。
- 非ゴール: 同じ種類のデバイスが 2 台あるときに見分けること（同じ絵になる。作者が了承）。
- 非ゴール: 切断中のデバイスの表示。
- 非ゴール: 表示のクリック（フライアウトを開くなど）、ツールチップ。
- 非ゴール: サブモニターのタスクバー、上・左・右に置いたタスクバー、表示位置の調整。
- 非ゴール: 本家への PR、macOS / Linux。
- アンチゴール: **トレイ（通知領域）に出すこと。**
- アンチゴール: アプリのボタンや時計に重なって、タスクバーが使いにくくなること。
- アンチゴール: 全画面のゲームや動画の上に表示が残ること。
- アンチゴール: 表示がクリックやフォーカスを奪うこと。
- アンチゴール: 表示の失敗（タスクバーが見つからない、表示のプログラムが落ちる、作れない）で、バッテリーの読み取り・トレイ・通知が止まること。
- アンチゴール: 本家のファイルに大きく手を入れ、取り込みのたびに衝突すること。

## 制約

- Windows 11 には、アプリがタスクバーに部品を足す公式の仕組みがない（deskband は使えない）。inzone と同じく、タスクバーの上に最前面の小さな窓を重ねる。
- アプリは Electron（Node）。トレイの位置と UI Automation によるアプリのボタンの位置は、Node や Electron からは取れない。
- この repo には、Windows に付いている C# コンパイラ（`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`）で小さな exe を作る仕組みがある（`scripts/build-batteries.js` → `src/main/system-batteries.exe`）。このコンパイラは C# 5 / .NET Framework 4 まで。inzone のコードは .NET 10 / 新しい C# なので、書き方を直して移す必要がある。
- ビルドは GitHub Actions の `windows-latest`（`build.yml`、`fork-release.yml`）。開発機は WSL で、ここでは exe を作れない（`build-batteries.js` は Windows 以外でスキップする）。
- トレイの絵は、実行中に画像を作らず、ビルド時に PNG にしている。実行中に画像を作ったとき、Windows のシェル（combase.dll）が落ちたため（`src/main/tray.js` のコメント）。表示のプログラムは Electron とは別のプロセスで GDI+ で描くので、この制約はかからない。ただし Electron の側では、実行中に画像を作らない。
- 画面の文字は、すべてポルトガル語の訳が要る（`test/i18n-screen.test.js`）。
- 作者の環境: Windows 11、モニター 1 枚（3440×1440、100%）、タスクバーは下・中央寄せ・ダーク（inzone の実機確認と同じ PC）。

## 検討した案

HUMAN が選んだ: **案 A**（2026-11-28）。

- **A. 小さな C# のプログラムが、位置の計算から描画までを全部やる（採用）**。inzone の `TaskbarProbe` / `TaskbarOverlayWindow` / `TaskbarOverlayPolicy` / `TaskbarOverlayController` / `TaskbarBatteryOverlay` を C# 5 に直して 1 本の exe にする。Node は、表示するデバイスの一覧を標準入力へ JSON の 1 行で送るだけ。動いている間のメモリは十数 MB で済む。実機確認済みのコードを再利用できる。本家のファイルへの変更が最も少ない。手間は C# 5 への書き換え。
- B. 位置だけ C# で測り、描画は Electron の透明なウィンドウでやる: SVG や翻訳をそのまま使えるが、常に出すページ 1 枚ぶんのメモリ（数十〜90 MB）が増える。物理ピクセルと Electron の座標の変換、手前に戻す処理がプロセスをまたぐなど、部品が増える。外した。
- （外した）C# を使わず、Electron の `screen` の情報だけで位置を見積もる: トレイとアプリのボタンの位置が分からず、重なりうる（アンチゴール）。

## 設計

### 見え方

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ⊞ 🔍   [アプリのアイコン…]      [🖱] 82%  [⌨] 45%  [🎧] 18%  ^ 🔊 📶 12:34 │
└──────────────────────────────────────────────────────────────────────────┘
                                 ↑ここに重ねる（トレイのすぐ左）
```

- 置き場所・背景・文字の色（タスクバーがダークなら白、ライトなら黒。`SystemUsesLightTheme` に追従）・高さと上下の中央寄せは、inzone と同じ。
- 1 台ぶんは「絵 + 数字 + `%`」。充電中は `%` のあとに稲妻の絵（`icons.js` の `flash`）を添える。台と台の間は、1 台の中の間より広く空ける（どこまでが 1 台か分かるように）。フォント・大きさ・間隔の細部は builder に任せる（目安: inzone と同じ、タスクバーの時計に近い見た目）。
- 絵の色は文字と同じ（ダークで白、ライトで黒）。残量が少なくても絵の色は変えない。
- 並び順は、**ウィンドウのカードの今の並びと同じ**（HUMAN が選んだ。2026-11-28。builder check の指摘 1）。設定の `sortMode` に従い、既定の `'urgent'` では `src/renderer/estimate.js` の `urgencyCompare` で並ぶ。つまり、充電していないものが先（その中で残量の少ない順）、次に充電中のもの（その中で残量の少ない順）。残量が同じなら `order` の順。手で並べる設定（`'manual'`）のときは `order` の順。残量が変わって並びが入れ替わるのは許す（作者が了承）。`sortMode` が変わったときも送り直す。`estimate.js` は `module.exports` があるので、Node の側でそのまま使う。

### 出すデバイス

- 保存されているデバイスのうち、**接続中で残量の値があるもの**だけ（`online !== false` かつ残量が `null` でない）。切断中・まだ読めていないものは出さない（作者が了承）。
- 古い残量は出さない（Claude の判断。builder check の指摘 3）。タスクバーには「Updated …前」の添え書きがなく、古い値を今の値と思い込むため。具体的には:
  - **この起動のあと、一度も読めていないデバイスは出さない**。前の起動で保存した `online` と `lastReading` だけでは出さない。
  - 読み取りに失敗し続けて、カードが "Can't read this device" を出す状態（`failedReads >= READS_BEFORE_REPORT`）では出さない。一度の失敗では消さない（カードと同じ基準）。
  - `'waiting for headset update'` のように、カードが残量を「今の値」として出していない状態も出さない。判定の細部は、カード（`src/renderer/app.js` の残量の下の行の決め方）に合わせて builder が決める。
- 隠しているカード（`hidden`）は出さない（Claude の判断。ウィンドウで見ないことにしたものだから）。
- 1 台もなければ、表示を消す。

### 残量が少ないとき・充電中

- 残量が **20% 以下**のとき、数字と `%` をオレンジにする（作者が了承した決まり）。しきい値は 20 に固定し、通知のしきい値（`notifyThreshold`・デバイスごとの `alertThreshold`）とは結び付けない。充電中でも 20% 以下ならオレンジにする（充電中は稲妻も添える）。
- 色は inzone と同じく、ダーク `#FF9F43`、ライト `#C2410C`。

### 絵

- 絵の名前は、ウィンドウと同じ決め方（`icons.js` の `deviceIconName`: カードで選んだ絵、昔の版で保存した絵文字の読み替え、なければ製品名とドライバからの推定）。Node の側で名前を決めて、表示のプログラムへ送る。
- `icons.js` は窓の中で読むスクリプトで、`module.exports` がない。本家のファイルを変えないため、Node の側では `icons.js` を `vm` で読み込んで `deviceIconName` を使う（Claude の判断。builder が、本家のファイルを変えない、より良いやり方を選んでもよい）。
- 絵の画像は、トレイの絵と同じく**ビルド時に PNG にしてリポジトリに入れる**。`icons.js` の全種類（`mouse` `keyboard` `headset` `mic` `speaker` `camera` `controller` `pen` `plug` と、充電の `flash`）を、白と黒の 2 色、表示倍率 100%〜200% で使える大きさで作る。作るスクリプトは fork の新しいファイル（例 `scripts/make-taskbar-icons.js`）にし、`make-icon.js` は変えない。置き場所・大きさの段・ファイル名は builder に任せる。
- 知らない絵の名前が届いたら、`plug` を使う。

### 表示のプログラム（C#）

- ソースは `src/main/batteries/TaskbarBattery.cs`（fork の新しいファイル。名前は builder が変えてよい）。`scripts/build-batteries.js` に、`system-batteries.exe` と同じやり方で `src/main/taskbar-battery.exe` を作る段を足す（`// fork:`）。作れないときは、ほかの exe と同じくスキップし、アプリはこの機能なしで動く。参照する .NET Framework のアセンブリ（WinForms、UI Automation の `UIAutomationClient` / `UIAutomationTypes` など）は builder が決める。
- ふるまいは inzone の実装と同じ。
  - 最前面のレイヤード窓（`WS_EX_TOPMOST` `WS_EX_LAYERED` `WS_EX_TRANSPARENT` `WS_EX_TOOLWINDOW` `WS_EX_NOACTIVATE`）に `UpdateLayeredWindow` で透過して描く。タスクバーより手前へ戻す見張りを 0.3 秒程度ごとに行う（一瞬裏に隠れるのは許す。隠れたままにはしない）。
  - トレイの左端は `Shell_TrayWnd` の子 `TrayNotifyWnd` から取る。アプリのボタンの右端は、UI Automation の ClassName `Taskbar.TaskListButtonAutomationPeer` の要素から取る。UI Automation は UI スレッドの外で呼ぶ。1 つも見つからないときは「位置を取れない」として隠す。
  - タスクバーの位置・大きさ、トレイの幅、表示倍率、解像度の変化と、Explorer の再起動（`TaskbarCreated`）に追従する。
- 出すのは次のすべてを満たすときだけ。どれかが崩れたら隠す（inzone の「いつ出すか」と同じ。1 と 2 だけがこの repo に合わせた）。
  1. 最後に届いた一覧に 1 台以上ある。
  2. 一覧の表示の幅が、トレイの左の空きに入る（アプリのボタンと重ならない）。**入らないときは全部隠す**（何台かだけ出すことはしない。Claude の判断。出ているものがすべてだと思い込まないように）。
  3. メインのモニターのタスクバーとトレイの位置が分かる。
  4. タスクバーが画面に出ている（自動非表示で隠れていない）。
  5. メインのモニターで、全画面のアプリが前に出ていない。
- 2 と 3 で出せないときは、Warn を 1 回だけ伝え、出せるようになったら Info を 1 回伝える（inzone と同じ）。4 と 5 は伝えない。

### Node とのやりとり

- Node の新しいファイル `src/main/taskbar.js`（fork）が、exe を起動し、標準入力へ JSON を 1 行ずつ送る。中身の形は builder に任せる。例:
  ```json
  {"devices":[{"icon":"mouse","level":82,"charging":false,"low":false}]}
  ```
- 送るのは、表示が変わるときだけ（同じ中身を続けて送らない）。
- 少ない・充電中の判定、絵の名前、並び順は Node の側で決める。exe は届いた一覧をそのまま描くだけ。
- exe は、標準出力（または標準エラー）へ、Warn / Info と予期しないエラーを 1 行ずつ書く。Node はそれを今のログ（`logLine`）へそのまま書く。書き方は builder に任せる。
- exe は、標準入力が閉じたら終わる。`system-batteries.exe` と同じく親のプロセス番号を受け取り、親がいなくなったら自分で終わる（Electron が落ちても残らないように）。
- exe が予期せず終わったら、Node は待ってから起動し直す。立て続けに落ちるときは、間を広げるか、あきらめてログに残す（細部は builder に任せる。何度落ちても読み取り・トレイ・通知は止めないこと）。
- 起動し直したら、最後の一覧を送り直す。

### 本家のファイルへのつなぎ

`// fork:` の目印を付ける。それぞれ数行にとどめる。

- `src/main/main.js`:
  - `broadcast` で、トレイの更新とは**別に**、`taskbar.js` へデバイスの状態を渡す（今のトレイの更新は `trayEnabled` のときだけ呼ばれるので、そこには入れない）。失敗はトレイと同じく `try` で包み、ログに書く。
  - デバイスが消えたとき（`setCardsChangedHandler` の `droppedId`）、並べ替え・隠す・絵の変更のときに、`taskbar.js` へ知らせる。どの IPC につなぐかは builder が調べて決める。
  - `settings:set` で、ON/OFF と並べ方（`sortMode`）の変更を `taskbar.js` へ知らせる。
  - 起動時（`app.whenReady`）に設定を読んで始め、終了時（`quitApp` / `before-quit`）に exe を止める。
- `scripts/build-batteries.js`: exe を作る段を足す。
- `src/renderer/index.html`: 設定画面の「System tray」の下に、トグルの行を 1 つ足す（題名は例 `Taskbar battery levels`、説明は例 `Show each connected device's icon and level next to the tray.`。文言は builder が決めてよい）。今のトグルと同じ `data-setting` の仕組みで、`app.js` は変えずに済む見込み（済まなければ、最小のつなぎを足す）。
- 翻訳: 足した文言の訳（ru / es / zh / he / pt）は、fork の新しいファイルに置き、本家の `i18n-strings.js` の訳とまとめる。そのためのつなぎ（`index.html` に `<script>` を 1 行、など）は builder に任せる。`test/i18n-screen.test.js` が通ること。
- 設定の既定値: `taskbarBattery`（真偽）、既定は **`false`**。`store.js` の `DEFAULT_SETTINGS` に 1 行足すか、`taskbar.js` の側で「なければ `false`」とするかは builder に任せる（設定画面のトグルが値なしでも正しく「OFF」と出ること）。

### 設定の反映

- ON にした瞬間に exe を起動し、今の一覧を送る。OFF にした瞬間に exe を止める（表示が消える）。再起動は要らない。
- `trayEnabled` が OFF でも、この設定が ON なら出す（別の設定）。
- 並べ方（`sortMode`）を変えたら、並べ直して送り直す。

### 失敗の扱い

- exe がない（Windows 以外、コンパイラがない、ビルドに失敗した）: 何も出さない。起動時にログへ Info を 1 回書く。設定のトグルはそのまま出す（fork 版は CI で必ず exe を作るため。Claude の判断）。
- exe の起動・書き込みの失敗、exe が落ちた: ログに書く。読み取り・トレイ・通知・ウィンドウは止めない。

## テスト

自動テスト（`npm test`、`node --test`。fork の新しいテストファイル、例 `test/taskbar.test.js`）:

- 出すデバイスの選び方: 接続中で残量あり → 出す。切断中・残量なし・隠したカード → 出さない。
- 並び: `sortMode` ごとに、カードと同じ順になる。`'urgent'` では `urgencyCompare` と同じ順（例: 充電中の 10% と充電していない 80% なら、充電していない 80% が先）。`'manual'` では `order` の順。
- 絵の名前: カードで選んだ絵、昔の絵文字の読み替え、推定、知らない名前のときの扱いが、`icons.js` と同じになる。
- 少ない判定: 20 → オレンジ、21 → ふだん、0 → オレンジ。充電中の 15 → オレンジ（稲妻も付く）。通知のしきい値を変えても結果は変わらない。
- 古い残量: この起動のあと読めていない → 出さない。失敗が続いてカードが "Can't read" の状態 → 出さない。一度だけの失敗 → 出す。
- 送る中身: 同じ中身は続けて送らない。変わったら送る。
- exe の起動・止める・起動し直し: 子プロセスを偽物に差し替えて、ON で起動、OFF で止める、落ちたら待って起動し直して最後の一覧を送り直す、立て続けに落ちたときの扱い。
- exe がないとき: 起動しようとせず、例外も出ない。
- 翻訳: `test/i18n-screen.test.js` がそのまま通る。

C# の側:

- 置き場所と出すか隠すかの判定（inzone の `TaskbarOverlayPolicy` にあたる、純粋な関数）は、inzone のテストを手本にした確かめ方を用意する。この repo には C# のテストの仕組みがないので、やり方（例: exe の確認用の引数で判定の表を走らせ、CI の Windows で `npm test` から呼ぶ）は builder に任せる。WSL では走らなくてよい（Windows でないときはスキップする）。

自動テストで扱わないもの（実機で確かめる）: タスクバーとトレイの位置の取得、窓の重なり、テーマと表示倍率の追従、全画面、Explorer の再起動。

## 実機での確認（インストールして）

`gh workflow run build.yml -R rurute/battery-hub --ref feat/taskbar-battery` で作ったインストーラーを入れて確かめる。inzone の実機確認（`../inzone-auto-switch/docs/manual-test-taskbar-battery.md`）で合格した項目のうち、作りが同じものは、ここでは軽く見るだけでよい。

1. 設定で ON にすると、接続中のデバイスがトレイのすぐ左に「絵 + 残量」で並ぶ。OFF にすると消える。どちらも再起動は要らない。初期状態（設定を触っていない）では出ない。
2. 絵と残量が、ウィンドウのカードの絵と残量に合う。カードで絵を変えると、タスクバーの絵も変わる。並び順もカードと同じ。
3. デバイスの電源を切る（切断する）と、そのデバイスが消える。入れると出る。全部切ると表示が消える。
4. 充電すると稲妻が付く。20% 以下のデバイスは数字がオレンジ（20% 以下のデバイスがなければ、確認用に値を差し替えたビルドで確かめてよい）。
5. タスクバーをクリックしたり、アプリを切り替えたりしても、表示が裏に隠れたままにならない。表示をクリックしても何も起きず、フォーカスも奪わない。
6. トレイのアイコンが増減しても、トレイの左に付いていく。
7. 全画面の動画やゲームで、表示が上に残らない。
8. アプリを終了すると、表示も消え、`taskbar-battery.exe` がタスク マネージャーに残らない。
9. トレイのアイコンを OFF にしても、タスクバーの表示は出る。
10. Windows のテーマをライトとダークで切り替えると、文字と絵の色が追従する（ダークで白、ライトで黒。オレンジはそれぞれの色）。
11. 表示倍率を 100% と 150% で切り替えると、位置と大きさが合い、絵がぼやけない。
12. Explorer を再起動（タスク マネージャーから）すると、置き直されて出る。
13. アプリをたくさん開いて、タスクバーのアイコンが表示にかかるほど並ぶと、表示が全部消える（アイコンに重ならない）。ログに Warn が 1 回だけ出る。アプリを閉じて空きができると、また出て、ログに Info が 1 回出る。
